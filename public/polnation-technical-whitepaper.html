1. Abstract

Polnation is an Agentic AI Earning platform deployed on Polygon PoS. The product uses an off-chain agentic earning engine to read public USDC balance data, apply balance-tier and risk rules, and surface daily earning eligibility without requiring users to deposit funds into Polnation custody.

The technical thesis is simple: the AI/agent layer can compute, rank, and automate earning logic, but the trust boundary must remain public and auditable. That boundary is the verified Polnation MerkleTree contract on PolygonScan.

  • Agentic earning engine - Reads public on-chain state, balance tiers, user eligibility, and operational guardrails before producing earning actions.
  • Verified MerkleTree contract - The Polygon contract 0x76f0d64bC0D41262aebBCc584679Ee1EBb22dd0d is listed on PolygonScan as a verified contract with Source Code Verified / Exact Match and contract name PolnationMerkleTree.
  • PolygonScan identity signal - The PolygonScan record surfaces the Polnation: Merkle Tree label/name-tag context, giving users a public explorer-level identity reference instead of an opaque contract address.
  • Scoped authorization - Polnation does not require an unlimited standing USDC approval. Where a permit-based flow is used, the user signs a specific authorization and the resulting action is visible on-chain.
  • Auditability - Users can inspect the verified Solidity source, ABI, owner, USDC address, and emitted events directly on PolygonScan.

Core Proof: Polnation's Agentic AI Earning system is not asking users to trust a hidden black-box contract. The MerkleTree contract is public, verified on PolygonScan, labeled in the Polnation context, and independently inspectable by any wallet user, auditor, or exchange risk engine.

3. Non-Custodial & Scoped Authorization Model

The most critical security property of Polnation is its non-custodial, scoped-authorization architecture. Understanding what this means requires knowledge of how ERC-20 token approvals and permit signatures work, and why Polnation avoids unlimited standing approvals.

3.1 What Are Token Approvals?

In the ERC-20 standard, approve(spender, amount) grants a third-party contract permission to call transferFrom() on your tokens. This is how DEXes (Uniswap), lending protocols (Aave), and bridges move your tokens.

⚠️ The Risk: Any contract with a non-zero approval on your tokens can call transferFrom(owner, recipient, amount) at any time to move your tokens — even without your interaction. Malicious or compromised contracts with approvals can drain wallets. This is the #1 attack vector in DeFi exploits.

10. Glossary

TermDefinition
Merkle TreeA binary hash tree where each leaf contains a hash of data, and each parent contains the hash of its children. The root hash represents all data.
Merkle RootThe single 32-byte hash at the top of the tree. Stored on-chain as a commitment to all user rewards.
Merkle ProofA compact set of sibling hashes (O(log N)) that allows verification of a specific leaf's inclusion in the tree.
keccak256The cryptographic hash function used by Ethereum and Polygon. Produces a 256-bit (32-byte) hash.
balanceOf()A standard ERC-20 function that returns the token balance of an address. Read-only, requires no authorization.
approve()An ERC-20 function that grants a spender permission to move tokens. Polnation Agentic Earning does not require an unlimited standing approval.
allowance()An ERC-20 function that returns the approved amount for a spender. Users should review this value for unexpected standing approvals.
transferFrom()An ERC-20 function to transfer tokens on behalf of an owner. In the PolnationMerkleTree flow, execution is bounded by user authorization and can be audited through contract events.
Non-custodialA design where the platform never holds, controls, or has access to user funds.
Polygon PoSA Layer 2 Proof-of-Stake blockchain built on Ethereum, offering low fees and fast transactions.
CheckpointA periodic snapshot of Polygon block state submitted to Ethereum L1 by validators.
ValidatorA node that participates in block production and consensus on the Polygon network.
stMATIC / MaticXLiquid staking tokens representing staked POL via Lido and Stader protocols, respectively.
