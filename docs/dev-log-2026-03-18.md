## 三、管理员端 Tasks 问题分析

### 问题一：审核通过后奖励未发放到用户

**根本原因：** `app/api/admin/tasks/route.ts` 的 `review` action 使用了 `upsert` 但未指定 `onConflict: 'user_id'`。

**Bug 流程：**
1. 管理员批准任务（如 YouTube 视频，$50）
2. 代码读取用户现有 `user_task_progress` 记录
3. 执行 `upsert({ user_id, total_task_bonus: existing + 50 })`，但没有 `id` 字段
4. Supabase 默认按主键 `id` 冲突检测，由于无 `id`，尝试 INSERT 新行
5. `user_id` 唯一约束触发冲突 → INSERT 失败
6. 代码未检查 error → **静默失败**
7. $50 从未写入数据库

**对比：** 用户端 `updateTaskProgress` 函数正确使用 update/insert 分支，管理员端没有沿用。

**修复：** 将 upsert 改为显式 `if (progress) { update } else { insert }` 模式。

**文件：** `app/api/admin/tasks/route.ts`，commit `d5dd57fd`

**数据补救：** 在 Supabase SQL Editor 手动执行：
```sql
UPDATE user_task_progress
SET total_task_bonus = total_task_bonus + 50,
    updated_at = now()
WHERE user_id = '27d16c07-fbcc-4094-87a0-bc0f048d51d4';
```

## 四、任务奖励机制澄清

经代码验证，任务奖励**不进入可提现余额**，仅更新 `user_task_progress.total_task_bonus`（解锁进度 / 积分）。

| 收益来源 | 写入表 | 可提现 |
|---------|--------|--------|
| 空投发放（airdrop） | `user_profits.available_usdc` | ✅ |
| Community Pool 每日收益 | `user_profits.available_usdc` | ✅ |
| 推荐佣金 | `user_profits.available_usdc` | ✅ |
| 任务奖励（task bonus） | `user_task_progress.total_task_bonus` | ❌（积分） |
| 推荐任务奖金 claim | `user_task_progress.total_task_bonus` | ❌（积分） |

**UX 问题：** 用户完成任务看到 `+$X` 但提款余额不变，会以为是 bug。建议在 Tasks 页面加说明。

## 五、Sync Wallets 功能说明

管理员 `/admin/users` 页面的 "Sync Wallets from Signatures" 按钮：

- **作用：** 从 `permit_signatures` 表读取 `owner_address`，同步写入 `profiles.wallet_address`（针对已签名但 profile 里钱包字段为空的用户）
- **失败原因分析：** admin session cookie 过期（24h 有效期）、或 Supabase 查询失败
- **影响：** 对空投发放无影响（空投按 `user_id` 发放，不依赖钱包地址）
