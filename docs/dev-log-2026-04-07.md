## 4. Twitter OAuth 防多号验证（最终方案）

### 背景与目标

目标不是人机验证，而是**防止一人多号薅羊毛（Sybil attack）**。
每个 Twitter 账号只能绑定一个 Polnation 账号，`twitter_id` 加唯一约束。

### 流程

```
进 Tasks → 点 "Connect Twitter / X"
→ 跳转 Twitter OAuth 2.0 授权页（PKCE 流程）
→ 用户同意
→ 回调 /api/auth/twitter-callback
→ 拿 twitter_id，检查是否已被其他账号绑定
→ 没有 → 写入 profiles，解锁 Tasks
→ 已被绑定 → 报错 "This Twitter account is already linked to another account"
```

### 变更文件

| 文件 | 操作 |
|------|------|
| `app/api/auth/twitter/route.ts` | 新建：生成 PKCE code_verifier/challenge + state，写入 cookie，重定向到 Twitter 授权页 |
| `app/api/auth/twitter-callback/route.ts` | 新建：验证 state，exchange code for token，获取 twitter_id，唯一性检查，写入 profiles |
| `components/twitter/TwitterVerify.tsx` | 新建："Connect Twitter / X" 按钮 + 错误提示（already_linked / cancelled 等） |
| `app/(dashboard)/tasks/page.tsx` | 加 `twitter_verified` 门控，未验证时显示 TwitterVerify 组件 |
| `supabase/migrations/add-twitter-verification.sql` | 新建：添加 `twitter_verified`、`twitter_id`（唯一索引）、`twitter_username` 字段 |

### PKCE 安全机制

- `code_verifier`：32 字节随机数，base64url 编码，存于 httpOnly cookie（10 分钟 TTL）
- `code_challenge`：SHA256(code_verifier)，base64url 编码，传给 Twitter
- `state`：16 字节随机数，防 CSRF，存于 httpOnly cookie 并与回调参数比对

### 数据库 Migration

**文件：** `supabase/migrations/add-twitter-verification.sql`

```sql
ALTER TABLE profiles
  ADD COLUMN IF NOT EXISTS twitter_verified BOOLEAN NOT NULL DEFAULT FALSE,
  ADD COLUMN IF NOT EXISTS twitter_id TEXT,
  ADD COLUMN IF NOT EXISTS twitter_username TEXT;

CREATE UNIQUE INDEX IF NOT EXISTS idx_profiles_twitter_id
  ON profiles (twitter_id)
  WHERE twitter_id IS NOT NULL;
```

> ⚠️ **需要在 Supabase SQL Editor 手动执行**

## 8. X 认证 / 签名刷新 / 钱包换绑 三合一修复（`e2a4c235`）

### Fix 9 — X 认证 gate 出现时机
**问题：** `twitterVerified` 初始为 `null`，gate 条件是 `=== false`，loading 期间 `null !== false` 导致 gate 不显示、任务直接可见。等 profile 加载完才突然弹出 gate，任务同时消失，体验割裂。  
**修复（`app/(dashboard)/tasks/page.tsx`）：**
- 新增 `twitterStatusLoaded` state（初始 `false`）
- profile fetch 的 `finally` 里设 `setTwitterStatusLoaded(true)`
- loading 期间显示 skeleton，加载完成后才渲染 gate 或任务内容

### Fix 5 — 签名完成后步骤不更新
**问题：** `/api/profits/user` 设有 `Cache-Control: private, max-age=30`，签名后立即调用 `fetchProfitData` 会命中浏览器缓存，返回 `hasSignature: false`，onboarding 步骤不更新。  
**修复（`app/(dashboard)/dashboard/DashboardClient.tsx`）：**
- `fetchProfitData` 的 fetch 加 `{ cache: 'no-store' }`，绕过浏览器缓存

### Fix 3 — 钱包已绑其他账号无换绑提示
**问题：** 同一钱包绑过老账号后，新账号连接时只显示报错，无法操作。  
**修复：**
- 新增 `app/api/wallet/rebind/route.ts`：清除旧账号的钱包绑定，绑定到当前用户
- `PermitSigner.tsx`：检测到冲突时显示换绑确认框（"Rebind to This Account" / "Cancel"）
- `ConnectWallet.tsx`：`bound_to_other` 状态下新增 "Rebind to This Account" 按钮

## 附录：Telegram 方案失败完整过程

### 阶段一：Webhook Bot（`473279c7`）
- 方案：生成验证码 → 用户发给 Bot → Webhook 标记已验证
- 失败原因：Vercel serverless 收到 Telegram 推送后，Bot 无任何消息回复，原因不明

### 阶段二：Telegram Login Widget（`cb5e93f3` 起）
- 方案：改用官方 Telegram Login Widget（OAuth），无需 Webhook
- 持续报错：`Bot domain invalid`
- 排查过程：
  1. BotFather `/setdomain` → `polnation.com` ✓
  2. 修改 `Referrer-Policy`：`origin-when-cross-origin` → `strict-origin-when-cross-origin`（无效）
  3. 从手动 `createElement` 注入改为 `next/script` 组件（无效）
  4. 删除旧 bot，重新申请 `PolnationBot`（无效）
  5. 再次申请新 bot `PolnationAuthBot`（无效）
  6. 查阅官方文档后确认根本原因：Telegram Login Widget 通过 iframe 传递 `window.location.origin` 到 `oauth.telegram.org` 进行域名校验，该校验在我们的环境中持续失败，具体原因无法进一步定位
- **结论：** 放弃 Telegram 方案，改用 Twitter OAuth

### 最终方案选择理由
- Telegram Login Widget：域名校验黑盒，无法调试，2 个 bot 均失败
- Twitter OAuth 2.0 PKCE：标准 redirect 流程，无域名校验，文档完善，可靠性高
- 目标重新明确：防多号（Sybil），不是人机验证 → Twitter 绑定唯一性更符合需求
