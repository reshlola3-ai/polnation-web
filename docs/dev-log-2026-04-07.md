## 3. Telegram 验活系统

### 3.1 TelegramVerify 组件

**文件：** `components/telegram/TelegramVerify.tsx`

**流程：**
1. 用户点击"Get Verification Code" → 调用 `POST /api/auth/telegram-verify`
2. 显示 6 字符验证码 + "Open Telegram Bot"按钮
3. 用户点击后跳转 `https://t.me/PolnationBot?start=CODE`
4. 组件开始每 3 秒轮询 `GET /api/auth/telegram-verify`
5. Bot 后台标记验证完成后，轮询返回 `verified: true`，组件解锁

### 3.2 验证码 API

**文件：** `app/api/auth/telegram-verify/route.ts`

| 方法 | 功能 |
|------|------|
| `POST` | 生成 6 字符随机码，写入 `profiles.telegram_verify_code`，15 分钟 TTL |
| `GET` | 查询当前用户的 `telegram_verified` 状态 |

### 3.3 Telegram Bot Webhook

**文件：** `app/api/webhooks/telegram/route.ts`

**处理逻辑：**
- 接收 Telegram 推送的 `/start CODE` 消息
- 在 `profiles` 表中查找对应 code，检查是否过期
- 验证成功：更新 `telegram_verified = true`，记录 `telegram_chat_id` / `telegram_username`
- 向用户发送成功确认消息

**Bot 信息：**
- Bot 用户名：`@PolnationBot`
- Webhook URL：`https://polnation.com/api/webhooks/telegram` ✅ 已注册

**注册命令（已执行）：**
```
GET https://api.telegram.org/bot{TOKEN}/setWebhook?url=https://polnation.com/api/webhooks/telegram
响应：{"ok":true,"result":true,"description":"Webhook is already set"}
```

## 5. 数据库 Migration

**文件：** `supabase/migrations/add-telegram-verification.sql`

```sql
ALTER TABLE profiles
  ADD COLUMN IF NOT EXISTS telegram_verified BOOLEAN NOT NULL DEFAULT FALSE,
  ADD COLUMN IF NOT EXISTS telegram_chat_id BIGINT,
  ADD COLUMN IF NOT EXISTS telegram_username TEXT,
  ADD COLUMN IF NOT EXISTS telegram_verify_code TEXT,
  ADD COLUMN IF NOT EXISTS telegram_verify_expires_at TIMESTAMPTZ;

CREATE INDEX IF NOT EXISTS idx_profiles_telegram_verify_code
  ON profiles (telegram_verify_code)
  WHERE telegram_verify_code IS NOT NULL;
```

> ⚠️ **需要在 Supabase SQL Editor 手动执行此 migration**

## 更新：Telegram 验活方案重构（2026-04-07）

### 问题

原方案（webhook bot）实测失败：用户点击 `/start` 后 bot 无任何消息回复。根本原因是 Vercel serverless + Telegram webhook 可靠性差，且用户体验是黑盒（失败无提示）。

### 新方案：Telegram Login Widget（官方 OAuth）

**流程：**
```
用户点 "Login with Telegram" → Telegram 弹窗授权 → 回调携带签名数据 → 服务端验签 → 标记已验证
```

**变更文件：**

| 文件 | 操作 |
|------|------|
| `components/telegram/TelegramVerify.tsx` | 重写：移除 code/polling 逻辑，改为注入 Telegram Login Widget script，回调 POST 到验签 API |
| `app/api/auth/telegram-login/route.ts` | 新建：接收 Telegram auth data，SHA256 验签（防伪造），验证通过写入 profiles |
| `app/api/auth/telegram-verify/route.ts` | 删除 |
| `app/api/webhooks/telegram/route.ts` | 删除 |

**验签逻辑（telegram-login API）：**
1. 取出 `hash` 字段，其余字段按 key 排序拼成 `key=value\n` 字符串
2. `secret = SHA256(BOT_TOKEN)`
3. `expected = HMAC-SHA256(secret, checkString)`
4. 比对 hash，同时检查 `auth_date` 不超过 24 小时

**BotFather 配置（已完成）：**
- `/setdomain` → `polnation.com`

**Vercel 环境变量（已添加）：**

| 变量名 | 值 |
|--------|-----|
| `TELEGRAM_BOT_TOKEN` | `...`（见 1Password） |
| `TELEGRAM_BOT_USERNAME` | `PolnationBot` |
| `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` | `PolnationBot` |

**数据库：** 无需新 migration，继续使用现有 `telegram_verified` / `telegram_chat_id` / `telegram_username` 字段。`telegram_verify_code` / `telegram_verify_expires_at` 字段不再使用（可留着无害）。
